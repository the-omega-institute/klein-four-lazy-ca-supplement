# Supplementary material: Generation by lazy and invertible cellular automata over the Klein four-group

Supplementary material for E. Alcalá-Arroyo, A. Castillo-Ramírez, H. Ma and W. Zhang,
*Generation by lazy and invertible cellular automata over the Klein four-group*.

This repository contains the exact enumeration programs and certificates for Section 6,
and a standalone Lean 4 / Mathlib formalization of the main membership criterion
(Theorem 1.1) and of the two cardinalities stated in the paper:

- `KleinFour.membership_iff`: a cellular automaton T lies in the monoid generated by the invertible and the lazy
  cellular automata if and only if it satisfies the criterion of Theorem 1.1;
- `KleinFour.membership_iff_orbits`: the same criterion in the orbit-image form used in the paper;
- `KleinFour.membership_card`: the generated monoid has 59,712 elements;
- `KleinFour.lazy_membership_card`: the monoid generated by the lazy maps alone has 4,007 elements.

All results depend only on the standard axioms `propext`, `Classical.choice` and `Quot.sound`
(see `axioms.log`); there is no `sorry` and no `native_decide`.

Build instructions and a description of the model are in `LEAN-README.md`
(Lean `leanprover/lean4:v4.33.0`, Mathlib `v4.33.0`).

## Reproduce Section 6 and Table 1

The [experiments directory](experiments/README.md) contains the recovered C++ BFS,
an independent Python/NumPy checker, and membership and shortest-word tables for
all 65,536 rules in each of the lazy-only and mixed monoids. These computations
run independently of Lean.

Requirements: a C++17 compiler, Python 3, and NumPy. If NumPy is not already
available, install it in a virtual environment:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r experiments/requirements.txt
```

From the repository root, run these commands sequentially:

```sh
mkdir -p experiments/build
c++ -std=c++17 -O2 -Wall -Wextra -pedantic experiments/compute_klein_closures.cpp -o experiments/build/compute_klein_closures
(cd experiments && ./build/compute_klein_closures)
python3 experiments/verify_klein_closures.py
(cd experiments && shasum -a 256 -c SHA256SUMS)
python3 experiments/generate_lazy_certificate.py --check
```

The BFS regenerates the two membership tables and the lazy-generator table.
The checker independently reconstructs all maps and generators, verifies every
certificate and every generator edge, and writes `experiments/table-1.csv` and
`experiments/closure-independent-verification.json`. Its Table 1 output is:

```text
Table 1. Numbers of elements at each shortest-word length.
Length k | l_L(T)=k | l_(U union L)(T)=k
0 | 1 | 1
1 | 54 | 565
2 | 678 | 8,806
3 | 1,894 | 27,424
4 | 1,218 | 19,004
5 | 156 | 3,870
6 | 6 | 42
Total | 4,007 | 59,712
```

These entries agree exactly with v5 Table 1. Both maximum shortest lengths are 6.
The checker also verifies the 4,006 nonempty lazy compositions and the 19,360
mixed-monoid elements satisfying Proposition 6.2's no-swap conditions. The mixed
generating set has 566 elements, including the identity; consequently 565 have
shortest length one. The shortest lengths use all 54 lazy maps and all 512 units.

The final command checks that the restored Python certificate generator reproduces
the existing `KleinFour/LazyData.lean` byte for byte. It does not run Lean or change
that file. Table 1's shortest-word lengths are verified by the independent
computational checker; the Lean formalization covers the results listed above.
